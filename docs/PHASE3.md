# Phase 3: cloud-ready build and live validation

Phase 3 (Google Cloud, a real mailbox) follows after the upload of the case on 27 Sep 2026. The code for it exists and is tested offline with fakes; nothing in the four-minute demo depends on it. The demo itself is described in [DEMO.md](DEMO.md) and its numbers in [ASSUMPTIONS.md](ASSUMPTIONS.md).

## Cloud-ready build (offline)

- **Test set v2** (26 documents, four languages, scans, a Peppol UBL e-invoice, an email-body invoice, a statement): defined in [TEST_SET_V2.md](TEST_SET_V2.md), expected results in `tests/golden_v2.yaml`. It reuses the seed of the case documents; document 26 comes from a supplier that is not in the vendor master. The two scans carry **simulated** confidences in their fixtures (12: 0.93; 13: 0.62 on the gross total and 0.71 on the invoice number) to exercise the human-review path; with a key, the values come from Gemini. It is loaded from the command line (`python -m app.seed --dataset v2`), not from the UI.
- **Structured e-invoices** (UBL XML) are read by `app/ubl.py` without any model call; the UI says so. Payment terms come from the due date minus the issue date; the terms note is only a fallback (cash-discount clauses such as Skonto are ignored).
- **Test set v2 details**: the Kaffee & Co documents use the reduced German VAT rate of 7% (food); French suppliers writing in French group thousands with a space; the two scans are full A4 pages at exactly 300 dpi.
- **Email-body invoices** (no attachment) have nothing to read: to-be sends them to Human review ("invoice only in the email body"); as-is has no reading for them, so the simulator does not post them.
- **Statements**: to-be answers a statement with no known invoice behind it as a supplier payment-status query; as-is has no document-type check and posts it as an invoice.
- **Real mailbox intake**: `app/intake_imap.py` reads new messages from one or two IMAP mailboxes and posts them to `POST /intake/webhook`, which registers the document under the scenario's rule, reads it and runs the gate at once (documents "B-W01", "B-W02" …, dataset `live`). Live documents carry real dates, are processed after the loaded sample set and are aged to today in the exception cockpit. A *Reset demo* removes them. The webhook is not advertised in the UI.
- **Model access**: `GEMINI_BACKEND=vertex` switches the same SDK to Vertex AI (`GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`); the extraction code does not change.
- **Not tested here**: everything that needs Google Cloud (Vertex AI calls, Cloud Run, Cloud Storage, Secret Manager, Cloud Scheduler, BigQuery) or a real mailbox. It is covered by unit tests with fakes; [DEPLOY_GCP.md](DEPLOY_GCP.md) lists the steps and the acceptance test to run once the project exists.

## Live validation with Gemini (25 Sep 2026)

- **Setup**: a Google AI Studio key with billing. `gemini-2.5-flash` is not available to new keys (404), so extraction fell back automatically to `gemini-3.8-flash`, the newest generally available Flash model. Busy-model errors (429, 500, 503, 504) are retried three times with growing pauses (a 429 waits the delay the server asks for) before the next Flash model is tried; a model found unavailable is not asked again in the same process.
- **Extraction**: every PDF of the case documents and of test set v2 (the UBL e-invoice and the email-body invoice need no model). All compared fields match the ground truth (identifiers normalised as the gate uses them, amounts to the cent). No critical field fell below the 0.80 threshold. Report: [LIVE_VALIDATION.md](LIVE_VALIDATION.md), regenerated by `make validate` from the cache, without calling the API. The validation ran before the renumbering of 25 Sep 2026 (then 14 case documents); the twelve kept PDFs did not change, so their cached readings still apply.
- **Document types**: the reminder copy (case document 2) and the account statement (v2 document 3) were read again once, so that the cache holds the new document types `reminder` and `statement`.
- **Ground truth correction**: the Nordwind account statement (v2 document 3) prints a balance only. Gemini returned no net total, which is right, so the fixture has `net_total: null` for statements.
- **Scans**: the fixtures give the two scans simulated confidences (above). The real model read both correctly and with high confidence, so in to-be the degraded scan (v2 document 13, a small non-PO invoice from the Berlin store's catalogue supplier) is posted through the card / catalogue commitment instead of going to Human review. This is the one gate result that differs from `tests/golden_v2.yaml`, which describes fixture mode. The confidence rule still sends a document to Human review whenever the model itself reports low confidence.
- **Owner-message drafts**: drafted live for the to-be exceptions and human reviews of the case documents; each names the right owner, supplier, invoice number, PO and SLA date. They are cached in `data/cache/drafts/`.
- **Cost**: the readings cost about half a US cent per invoice at Google's list price of 25 Sep 2026.
- **Committed cache**: `data/cache/` is part of the repository, so a clone shows real model output without a key. `tests/test_validate_live.py` fails if a change to the gate or the normalisation stops the cached extractions from giving the expected results.
